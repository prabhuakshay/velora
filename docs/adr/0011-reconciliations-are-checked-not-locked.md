# Reconciliations are checked, not locked

A Reconciliation is a checkpoint on an Account (a date and the bank's balance that day), not a lock on the Splits it covers, and not a flag ticked on each Split. Nothing stops a later edit, delete or back-dated Transaction from moving the Balance on a reconciled day; instead each Reconciliation is checked against the Balance whenever it is shown, and one that no longer matches shows how far off it is. Locking would have to guard every path that writes Splits, including Schedules that post themselves, Drafts posted late and Merges, and would block those automatic paths; a computed check can never drift out of step with the Splits. Per-Split check-off, which copes with dates that differ from the bank's, was set aside as more work than one user recording dates as they happen needs.
