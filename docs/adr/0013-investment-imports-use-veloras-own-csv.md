# Investment Imports use Velora's own CSV, not statements or broker files

Investment Events come in through one CSV format that Velora defines and also exports: date, account, ISIN, instrument name, type, units, price, amount, charges, the new ISIN for a Merger, an optional reference and a note. Importing CAMS or KFintech statements, NSDL or CDSL CAS PDFs or each broker's tradebook directly was set aside, because those formats belong to others and change without notice. A changed statement layout would break imports with no fix in Velora's control, and every new broker would need its own parser. The user fills in the CSV from whatever they have instead, which costs some copying but makes the file the one contract Velora has to keep stable. Instruments are keyed by ISIN in the file, because the AMFI and NSE Price lists both carry it. An import is checked in full and shown as a preview before anything is applied. It is applied all at once or not at all, and Investment Events already recorded are skipped, so uploading a file again is safe. Events dated before an Investment Account's Opening Balance date only build Lot history and post no Transactions, because their money is already inside the Opening Balances.
